# data-to-paper v2: explicit response contracts

`data-to-paper-explicit-state-v2-dev` is a separately identified development
revision motivated by the six planning-schema failures in the
[v1 pilot](EXPLICIT_STATE_DATA_TO_PAPER_PILOT_V1_REVIEW.md). That cohort, its copied
runtime and all responses/outcomes remain immutable.

## Change and scientific boundary

Each stage now supplies an exact list of top-level JSON keys, a flat response
example and explicit prohibitions on wrapper/extra fields. The planner must
return its seven fields directly and leave formula generation to the coder.
The examples contain marked placeholders for hypotheses and chosen measurements;
they are interface illustrations, not recommended scientific models. The coder's
affine shape illustrates parameter placement, and the report example illustrates
computed-reference syntax. These examples can influence proposals and are part
of the frozen method configuration, not an invisible transport correction.

The revision clarifies that the ban on numerical formula literals applies to
expressions; exact cohort counts and evidence identities may be copied into their
specified metadata fields. Numerical report prose still requires computed
references. The prompt does not relax parsing or unwrap failed responses.

The scientific loop, strict guards, one analysis plus one failure-only repair,
post-freeze statistics, one report-only repair, model roles, fitting budgets,
three nomination slots, train/dev custody and assessment restrictions are all
inherited from v1. A new policy, request tag, source snapshot, worker identity and
configuration hash prevent silently resuming v1 under the new prompts.

## Execution and evidence

The module interface is `python -m principia_asd.paper_v2_jobs` with `prepare`,
`run`, `resume` and `status`; preparation requires settings and `--scenario`.
A matching frozen cohort uses `principia_asd.bound_pilot --protocol paper-v2`.
The monitor displays the protocol alongside computed statistics and report guards.
The earlier selectable data-to-paper adaptation remains unchanged.

Engineering verification exercises all stage shapes, rejection of wrapped/extra
fields, target aliases and test-selection plans, three hard exits around paid
repairs, separation from v1 cached requests, immutable terminal reads and all
three nomination slots. Synthetic fixtures are disclosed and cannot establish
live-model or scientific performance. Live evaluation remains a separate frozen
engineering pilot; private-test assessment and public ranking are not authorized.

The source license/revision, adapted workload and unsupported capabilities remain
as documented in [the v1 method description](EXPLICIT_STATE_DATA_TO_PAPER.md).

## Live pilot and interactive selection

The [verified v2 pilot](EXPLICIT_STATE_DATA_TO_PAPER_PILOT_V2_REVIEW.md) retains
all eight assignments: two complete, four incomplete reports and two unsupported.
All six compatible tasks executed one analysis. The dedicated development UI and
CLI selection now use v2; existing saved runs always retain their original
protocol. The method card discloses the pilot's incomplete-report rate. Private
test evaluation, public ranking and scientific-performance claims remain unavailable.
