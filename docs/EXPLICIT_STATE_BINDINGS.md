# Explicit scalar state — development contract

`principia_asd.engine.bindings` implements `explicit-scalar-lineage-v1-dev`. It is an opt-in development API. The separate `host-search-explicit-state-v1-dev` path connects it to real train fitting, normalization, kernel promotion, immutable submission and deterministic assessment. `principia-explicit-state-protocol-v1-dev` adds the model-role protocol and development selection, verified with scripted responses and real local fits. The dedicated development worker and append-only checkpoints now pass installed, offline process-restart tests. **A separate UI/CLI development option is now available. The [v2 live pilot](EXPLICIT_STATE_PILOT_V2_REVIEW.md) completed all six supported cases, with two unsupported assignments retained. Public ranking and symmetric comparison integration remain pending.** No existing method or evaluator version is silently replaced.

The host registers complete source artifacts, addressed by a content hash and a value path. A model can reference an existing binding ID but cannot establish provenance by attaching its own label. Source artifacts distinguish `train_fitted`, `train_statistic` and `fixed_scientific` scalar values. Dev/test scope, incomplete source computations, changed hashes and opaque arrays are rejected. The trusted host must still ensure the receipt describes a real permitted computation: a hash is an integrity check, not proof that a model's claim is true.

Every kernel expands into the same bounded numerical AST used by ordinary expressions. All literal values, including structural zero/one clipping bounds, must use explicit host bindings. This strict development policy rejects copied decimal coefficients instead of guessing their origin. Only final-stage parameters remain in the `parameters` map. No lookup table, fitted encoder or arbitrary Python routine can masquerade as one scalar primitive.

Accounting distinguishes:

- final-stage fitted parameters;
- inherited fitted scalars;
- train-derived statistics such as a mean and standard deviation;
- fixed scientific/structural constants;
- complete expanded operations and source records.

Shared aliases of the same source value count once. Equal values from different source computations remain separate. Renaming or inlining a kernel does not reduce expanded complexity. Final plus inherited fitted scalars have a combined limit of eight; the bounded registry retains statistics separately. Scalar-state bytes use an explicit float64 encoding, separate from provenance metadata. These counts are **not statistical degrees of freedom**. Upstream measurement processing remains outside this expression contract and must be reported separately.

`verify_program` rebuilds a compiled record from its bound sources and rejects mutations before execution. No provider or evaluator access is required. `scripts/verify_state_bindings.py` demonstrates the archived SHED witness on seven synthetic input rows: two final parameters plus three inherited coefficients produce bit-identical predictions. This is an engineering regression fixture, not an independent scientific result or a replacement score.

## Executable host integration

`engine.bound_search.BoundSearch(task, train, dev)` accepts numeric measurements with sample/group identities. It rejects overlapping train/dev identities or groups, keeps its own input copies, and has no file, evaluator-vault or provider interface. Its task stability ranges are derived from train. `normalization(input_name)` computes train-only mean/std and returns registered references. Constant columns are rejected rather than silently replaced with a scale. The fixed inventory contains only structural zero, one and two; a model cannot introduce a new fixed coefficient.

`fit(expression, initial, bindings=..., kernels=...)` validates expansion and the combined eight-fitted-scalar cap **before fitting**. All supplied parameters are optimizer initial guesses; they cannot become unfitted fixed state. SciPy least squares uses train residuals, with 60 solver function evaluations per attempt and an additional global count of every actual residual call, including finite differences. The default fitting objective is train squared error standardized by train target std; log-MAE tasks use squared log residuals. This is an explicit fitting objective, not a claim that it minimizes each task's final metric. Dev data supplies assessment only. Nonconvergence, nonfinite train domains and invalid development outputs remain failed candidates.

Successful fit receipts bind the train/task hashes, expression template, fitted program, initial values, optimizer/version and exact residual-call count. `promote(candidate_id)` returns a reusable expression whose fitted coefficients are source references. A second fit reports its own parameters separately from inherited coefficients and train statistics. Shared state is deduplicated by source identity, never by equal numerical value.

`freeze()` retains every candidate, failed request and resource count, and closes the inquiry. Subsequent fitting, normalization and promotion fail. Returned cards and frozen records are independent copies. CPU time is process CPU time. The standalone API does not itself provide OS isolation; the dedicated development worker adds one numerical thread, a 4 GiB RSS watchdog, the original 40-minute wall envelope and a shared four-worker semaphore. This is bounded numerical AST execution, not an arbitrary generated-Python sandbox.

`evaluate.bound.evaluate_bound_candidate(frozen, expected_sha256, candidate_id, rows, targets)` requires a freeze hash supplied by trusted host storage. Candidate-provided self-hashes cannot establish custody. It verifies source, task, candidate, program and final-fit bindings, then uses the existing accuracy/stability procedures with the explicit-state simplicity profile. Reassessment performs no fitting or model calls. All receipts carry `ranking_authorized: false`; the legacy evaluator rejects bound rules, and the Pareto helper excludes these development receipts. Old receipts without this explicit opt-out retain their previous behavior.

Run `python -I scripts/verify_bound_search.py` from an environment containing the installed wheel. It executes two real synthetic fits with a promoted kernel, preserves a rejected decimal and a failed domain fit, freezes, round-trips JSON, and assesses reproducibly without APIs. The second rule records **two final-stage coefficients, two inherited fitted coefficients and two train statistics**. The receipt is `docs/BOUND_SEARCH_VERIFICATION.json`; it is engineering evidence, not a new scientific trial or replacement leaderboard.

## Model-role protocol and development selection

`engine.bound_engine.BoundEngine` accepts the same train/dev measurements plus an existing provider gateway and explicit run identity. The four exact default model IDs remain in `methods.registry.DEFAULT_ROLES`; incomplete or unconfigured mappings fail rather than substituting a model. This development protocol currently supports one to eight numeric inputs. Wider tasks require a reviewed new configuration rather than hidden measurement truncation.

The host makes two weak-prior fits (constant and first-input affine). Each of two rounds then runs GLM planning, DeepSeek coding, up to two host compositions and Qwen criticism of executed results. The planner may propose up to three new kernels; the frozen local allocation composes the first two. The coder may propose two rules. Prior critiques, successful candidates and failed fits enter subsequent development context. Selected earlier fits are promoted through explicit state references. The final Kimi report receives already frozen nominations and cannot nominate new rules. The maximum normal dispatch is seven requests; the existing gateway remains responsible for capability verification, credential custody, monetary reservation and durable paid-call receipts.

Model responses are bounded JSON, not Python commands. Kernel patches cannot supply source artifacts, override existing kernels, insert numeric literals or introduce fitted parameters. Rules use host state names and fitted initial guesses. Task fields and measurement previews are explicitly allowlisted; previews state their six-row maximum and the full train/dev counts. Oversized total context fails before dispatch instead of silently dropping evidence. Malformed responses, wrong response/model IDs and unresolvable references are retained; no automatic repair call is made. A provider exception stops the protocol. Reusing a terminal in-memory engine returns its completed record without additional requests. Use the separate checkpoint wrapper below for process restart. The unwrapped in-memory API alone does not supply durable recovery.

The development selection policy uses dev error, expanded weighted operations and **all learned scalars**, including inherited coefficients and train statistics. It deduplicates repeated fits of one structure, preserves distinct fixed structural constants, takes the development Pareto candidates before other distinct structures, and retains all unselected candidates in the submission. Its three nomination slots never shrink: missing nominations are explicitly `unfilled`. This selection is not a public numerical leaderboard and has no test feedback.

The nomination manifest binds the host submission, protocol configuration and selected slots before reporting. `evaluate.bound.evaluate_bound_nominations` requires independently trusted hashes of both that pre-report manifest and the completed engine receipt. It assesses every nominated slot, retains unfilled slots and failed/incomplete method status, and makes no fit or model calls. Mutated nominations, source state, configuration or a failed-to-complete relabeling are rejected. Development receipts remain excluded from historical/public Pareto ranking.

Run the installed-wheel proof with:

```bash
python -I scripts/verify_bound_engine.py --workspace /path/to/private/engineering-fixtures
```

It simulates seven gateway replies and executes real train fits, then serializes a frozen submission and assesses all three slots twice. The synthetic records are saved outside upload roots; `docs/BOUND_ENGINE_VERIFICATION.json` records hashes, configuration and checks. It does **not** establish live model capability, discovery quality or comparative performance.

The separate UI method is now connected. Four [fixed controls](EXPLICIT_STATE_CONTROLS.md) share the numerical host, state accounting, development selection and checkpoint journal, with a dedicated macOS worker and frozen input/source launch bindings. Relevant adaptation integration and cohort verification remain pending. Freeze source, provider, data and method configurations before a new comparison. Do not relabel the historical v5 Pareto front as corrected; its original candidate selection cannot be repaired by changing exported counts. Dimensional legality, independent uncertainty, upstream processing and scientifically justified perturbation standards remain separate admission gates.


## Durable development worker

`engine.bound_checkpoint.DurableBoundRun` records an immutable intent and completed checkpoint around each of the 15 protocol operations. Each record binds its predecessor and contains the host-owned fitted sources, candidate archive, failures, counters and method state. The manifest binds the exact task/train/dev context, roles, generation limits, provider configuration and installed Python/numerical/source versions. A different configuration or runtime cannot resume the same identity. Checkpoints belong only in the private workspace; they are not public model traces or release inputs.

Restart restores committed numerical work rather than refitting it. Model payloads have canonical key and kernel ordering so round-tripped state does not silently change a paid request. An interrupted provider operation uses `SiliconFlowClient.recover_completed`, which has no dispatch path and verifies both the cached payload and response against the settled ledger entry. Missing, reserved, unknown, truncated or mutated responses cannot trigger a paid retry. If a local operation was interrupted before committing, the job enters `recovery_required`: its unrecorded numerical work remains unknown, and the framework does not reset its budget or automatically refit. This is a deliberate recovery boundary, not a claim of arbitrary instruction-level continuation.

A per-run nonblocking file lock prevents duplicate execution. Downtime consumes the original wall-time allowance; completed jobs return their immutable result without further fits or calls. CPU accounting accumulates committed worker CPU across restarts. Uncommitted CPU/optimizer work is explicitly unresolved when a local operation is interrupted, rather than reported as zero. The checkpoint hashes detect corruption under trusted local custody; final evaluation still requires an independently trusted nomination/result hash.

`python -m principia_asd.engine.bound_worker --folder PRIVATE_RUN --settings PRIVATE_SETTINGS` is a separate engineering entry point. It accepts only a direct child of the configured private `bound-runs/` folder and a new immutable request with scope `engineering_only_explicit_state_v1`, matching run identity, scenario path, roles, limits and attempt cap. The worker reads only contract/train/dev, uses the existing global CNY 3,000 ledger, caps the attempt at CNY 12 or less, and has no evaluator stage. The application and CLI call it only for the separate explicit-state development option. Old campaign drivers remain unchanged. The separately frozen live engineering pilot is documented in `EXPLICIT_STATE_PILOT.md`; it is outside the primary ranking.

The installed proof is reproducible with:

Both resume with exactly seven unique mocked dispatches, six fits and 46 optimizer evaluations. A third process reads each finished result unchanged. The receipt is `docs/BOUND_RECOVERY_VERIFICATION.json`; all real API usage is zero. Unit fixtures additionally cover all 15 committed boundaries, all seven provider boundaries, missing caches, interrupted local fits, changed inputs/configuration/runtime, mutations, duplicate workers and expired wall budgets. These are engineering checks, not live-model or scientific results.

## Interactive development use

In the local app, select **Principia Engine · explicit-state development**. Choose **Engine protocol v2** (recommended) or original v1 explicitly. Select a registered scenario or import grouped numeric CSV measurements, then configure the four model roles and a cap up to CNY 12. This protocol accepts one to eight inputs and freezes seven requests, sixteen fits, 4,096 optimizer evaluations and a 40-minute wall envelope. The task objective is fixed. The run produces three nomination slots, including unfilled ones, and makes no private-test assessment or leaderboard update.

The run monitor provides cancellation, frozen-result download, expanded expressions and state-source inspection. A separate **Engine development** history filter keeps these attempts identifiable. Resume is offered only as a preliminary eligibility hint: the worker revalidates the original copied runtime, inputs, configuration and checkpoint chain. A completed cached provider response can be recovered without dispatch; unknown billing and uncommitted local computations cannot. Cancellation is terminal. Local state stays under the private workspace’s `bound-runs/`; the UI never exports its credential settings.

CLI equivalent: `principia-asd run --scenario SCENARIO --method principia_engine_explicit --protocol v2 --settings PRIVATE_SETTINGS`. To recover an eligible interrupted run, use `principia-asd resume PRIVATE_RUN --settings PRIVATE_SETTINGS`; the saved launch binding governs execution. Legacy `evaluate` and `replay` commands explicitly reject development-only records rather than interpreting them as historical Rule Cards.

The browser proof uses `scripts/serve_bound_ui_fixture.py --workspace PRIVATE_FIXTURES` on a separate port. Its scripted replies exercise the actual controller, checkpoints and numerical fitter, with a deliberate interruption after the two initialization fits. Resumption completes six total fits, 46 residual evaluations and seven scripted requests. It does not exercise live provider transport; installed worker transport/recovery is verified separately. See `BOUND_INTERACTIVE_UI_VERIFICATION.json`.
